## C. The Store

`plugins/evidence/store.py`. B2 decisions D2 (filesystem), D3 (UTF-8 JSON, one
record per file at `<evidence_id>.json`) and D4 (two directories).

```text
EvidenceRecord -> to_stored_mapping() -> UTF-8 JSON -> evidence/staged/<id>.json
filesystem bytes -> UTF-8 decode -> json.loads -> load_stored -> EvidenceRecord
```

### The two tiers are two types

```text
StagedEvidenceStore     write · read · contains · list_ids · discard
PromotedEvidenceStore   read · contains · list_ids · discard (refused)
```

**A promoted store has no `write`.** §20.3 makes promotion a human act — same
`evidence_id`, `content_digest`, `record_digest` and bytes, a new location and
nothing else — so there is no operation by which AI-05 adds a record to the
durable tier. `admit_to_store` refuses a store without one, with a `TypeError`
naming the boundary, before it parses anything.

`discard` is present on both and raises on the promoted one, and that asymmetry
with `write` is deliberate. §19.2 makes `discard` a **tier-conditional**
operation — "staged may be discarded; promoted MUST NOT be deleted" is one rule
with two outcomes — so the operation exists and naming the refusal is how the
prohibition is stated. `write` is not tier-conditional: creating a record is what
the staged tier is for, and a method that exists only to refuse is a signpost
rather than a boundary.

### What it does not do, and how that is checked

```text
computes content_digest or record_digest   it imports nothing from
                                           plugins.evidence.digests, so it has
                                           no way to. Asserted against the
                                           source by AST, not promised.
canonicalizes                              §15 canonicalization is B1's and ran
                                           earlier; the Store writes the mapping
                                           it is handed, in the order handed
repairs or rewrites                       no method returns a corrected record
regenerates an evidence_id                 it reads the one it is given
promotes                                   no promotion method exists, and the
                                           promoted tier has no write at all
deletes a promoted record                  discard raises on the promoted tier
infers supersession                        no duplicate_of, revision, merge or
                                           dedup machinery exists
```

The write path reads `record.integrity.content_digest` once, to refuse a record
that has no digests. That is a precondition — an unwritten record would produce
a file `load_stored` could never read back — and not a calculation.

### Atomic, and never an overwrite

A record is written to a temporary name in the same directory, flushed, fsynced
and then **linked** into place. `os.link` is atomic and fails if the target
exists, which yields two properties at once:

```text
no partial file is ever visible under the record's real name
an existing record is never silently replaced
```

The temporary name does not end in `.json`, so an interrupted write cannot be
listed as a record. A collision is `DuplicateEvidenceId` and leaves the existing
bytes byte-identical.

### The id is validated before it becomes a path

`_path` runs the contract's own `G-EVIDENCE-ID` (`^ev-[0-9a-f]{16}$`) before
joining. A value containing a separator, a drive letter or `..` is refused
rather than joined, so `read("../../etc/passwd")` is impossible rather than
merely unused. Parametrized over traversal, absolute, wrong-width, uppercase and
non-hex ids, and over non-strings.

## E. Admission pipeline

`admit_to_store(raw, *, store, clock)` in `plugins/evidence/admission.py`.

```text
admit(raw)                     §30 steps 1-13, unchanged
store.contains(evidence_id)    §30 step 14
store.write(record)            the write §30 exists to gate
```

`admit()` is unchanged apart from documentation; the two entry points are
separate functions, not one with a mode. Nothing reimplements a B1 rule, the P1
workspace rule or the P2 loader — a test asserts that `admission.py` imports
neither the grammar nor the canonical projection.

### Uniqueness

```text
duplicate evidence_id      REJECTED, DUPLICATE_EVIDENCE_ID
                           detected before the write and enforced again by the
                           Store; the existing record is left byte-identical
                           and no second file appears
duplicate content_digest   ACCEPTED. Two records making one claim are two
                           events (§8.2): different evidence_id, same
                           content_digest, different record_digest, both stored.
                           content_digest is not a key of this store.
```

D8 keeps the halves apart: the *rule* is admission's, the *detection* is the
Store's, and neither module holds both.

### Failure semantics

```text
REJECTED      a contract or content violation. Nothing is stored. §30's
              "stores nothing" is asserted per rejection reason.
UNAVAILABLE   a write that failed for a reason other than collision, with
              STORAGE_FAILURE. The record was valid and storage did not
              complete (§22.3) — a different condition from REJECTED, and it
              keeps a different reason code.
```

No record describing a failure is written. §22.3: the failure belongs in the
return value.

## F. Lifecycle

No state machine was built, and no lifecycle field was added to `EvidenceRecord`.

```text
staged     write · read · discard
promoted   read · integrity-verified · not writable · not deletable by AI-05
promotion  a human act. Same evidence_id, content_digest, record_digest and
           bytes; a new location only. Not automated, and no API exists for it.
```

`discard` removes a whole record or raises. It refuses on the promoted tier with
`PromotedRecordNotDiscardable`, so §19.2's prohibition is enforced by the code
path that would otherwise have deleted the file rather than by nobody calling
it. The absence of a delete-promoted operation is asserted directly.

The promotion invariants are verified by hand: a test copies a staged record's
bytes into the promoted directory — the act a human performs — and then asserts
that the bytes, `evidence_id`, `content_digest` and `record_digest` are
unchanged and that the promoted read returns the same `EvidenceRecord`. That
tests the frozen invariant; it does not implement the operation.

### Two things were found and fixed, and both are worth recording

**Adding the Layer 0 check broke an existing AI-02 test.**
`tests/unit/test_live_verification.py::TestLiveOnlyTransport::
test_the_http_transport_is_confined_to_the_live_path` is a guard that scans
`scripts/` for the transport's name, which the first version of this check
contained. The fix was not to exempt the file: it was to replace the denylist
with an allowlist, which is a better check and happens not to spell the name.
AI-02 was not modified. The full suite is green on the final head.

**The review found a programmatic promotion path, and it was real.**
`EvidenceStore(root, tier=PROMOTED)` accepted `write`, so
`admit_to_store(raw, store=promoted)` stored an ordinarily admitted record
directly in the durable tier. The absence of a `promote()` method did not
establish that promotion was impossible; a store that accepts an unearned record
is evidence that it was not.

The fix is structural rather than a guard: the tier is now a **type**, and
`PromotedEvidenceStore` has no `write` at all — not on the instance, not in
`vars()`, not in `dir()`. `admit_to_store` refuses a store without one, before it
parses anything, with a `TypeError` naming the boundary. No `promote()` or
`publish()` was added, no `allow_promoted` flag exists, and the
`AdmissionOutcome` vocabulary was not touched — the problem was a store target,
not an admission result.

The promoted tier still reads, still verifies integrity on read, still refuses
`discard` with `PromotedRecordNotDiscardable`, and still lists. The promotion
invariants are verified by a test that performs the human act itself.

## L. Residuals

- **`to_mapping` still orders collections** (P2 audit F2). Unchanged by P3. A
  choice for deterministic bytes, not a contract requirement.
- **`to_stored_mapping()` does not refuse an unwritten record.** Unchanged (P2
  F4). `Store.write` *does* refuse one now, which is the boundary that matters:
  the record can no longer reach a file.
- **`EvidenceRecord.from_stored_mapping` still does not exist** (P2 F3). The
  stored entry point remains `stored.load_stored`.
- **The Store's Python surface is provisional.** `read` returning an
  `EvidenceRecord` and `list_ids` returning a tuple are implementation choices;
  D11 has not been resolved and the module says so.
- **A record that is accepted but never written** is possible: `admit()` remains
  available and stores nothing by design, so a caller can reach §30 step 13 and
  stop. That is the P2 surface and was left alone.
