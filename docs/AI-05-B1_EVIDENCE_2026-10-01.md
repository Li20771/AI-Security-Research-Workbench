### T35 architecture boundary — checked independently

§30's T35 requires that `plugins/evidence` be parsed with `ast` and shown to
contain no network client, no `subprocess`, no `eval`/`exec`/`compile`, no
`routing`/`tools` import and no secret logging. That check was re-run here over
all 7 production modules rather than taken on trust:

```text

```

The check bans the *builtin* names. `re.compile(...)` appears throughout
`grammar.py` and is required — the contract's thirteen grammars are defined as
patterns — so a check that banned the bare attribute name would report false
positives. It bans `compile` only as a bare builtin call.

A second boundary was checked at the same time, because B1's own non-goals
depend on it. **There is no storage in B1**: no `json`, `yaml`, `sqlite3`,
`pickle`, `shelve`, `dbm`, `pathlib` or `io` import, and no builtin `open()`:

```text

```

### Cross-package imports, and why they are not boundary leaks

`plugins/evidence` imports from `plugins.guard`, `plugins.context` and
`providers`. The contract requires this rather than forbidding it: §3 states
that vocabularies frozen elsewhere — AI-03's `ItemKind`, `StatusValue`,
`Freshness`, AI-04's `GuardDecision` — are **imported, not restated**, because
two definitions in one repository means one of them is eventually forgotten.
§15 likewise imports AI-04's §20.2 serialization rules instead of restating
them, and §14.9 defines `G-MODELREF` as the composition of AI-02's
`PROVIDER_ID_RE` and `MODEL_ID_RE`.

The imports actually present are:

```text

plugins.guard.vocabulary    GuardDecision                (frozen elsewhere)
```

What is **not** imported is AI-04's semantic projection or its evaluator: AI-05

## F. The producer direct-proof — added, and why

The final conformance review raised one non-blocking gap in the evidence itself.
`producer`'s frozen semantic classification was proven **indirectly**: the suite
asserted the classification against the §15.2 table, and proved the operational
half by observing that `producer_version` moves only `record_digest`. It could
not prove the *semantic* half by varying `producer`, because §6.5's registry
fixes exactly one token per admitted event, so a second record differing only in
`producer` is rejected before any digest is computed.

**Judgement: worth closing, and it was closed** — in commit `39ddd27`, as a
test-only change.

```text
39ddd27  test(ai-05): assert the producer semantic classification directly
         1 file changed, 81 insertions(+), 0 deletions(-)
         tests/evidence/test_models.py only
         no production code, no contract, no digests.py, no AI-02/03/04
```

Two tests were added, next to the indirect test they complement, inside
`TestT8OperationalFieldsAreIndividuallyExcludedFromTheContentDigest`:

```text
test_the_producer_is_carried_by_the_content_projection
    content_projection(record)["producer"] == the registered token ("ai-03")
    "producer_version" not in content_projection(record)

test_the_same_holds_for_the_other_five_admitted_events
    the same assertion for one case per §6.5 registry row, so it is not
    accidentally true of a single producer
```

Both read the **real public projection of validly admitted records**. No invalid
record is manufactured, the registry is not touched, and no internal backdoor was
added to reach an unadmittable state.

### The assertion was checked for vacuity rather than assumed to bite

A test that cannot fail is not evidence. The classification was therefore
mutated in memory — `producer`'s row flipped from `INCLUDED` to `EXCLUDED` — and
the projection re-read, with no file on disk modified:

```text
baseline  'producer' in projection: True   | value: ai-03
mutated   'producer' in projection: False
VERDICT: NON-VACUOUS (assertion would fail on regression)
```

The assertion is therefore load-bearing: it fails if the frozen classification
is ever changed.

## G. C11 — a contract test-model limitation, recorded and not worked around

`docs/AI-05_EVIDENCE_EXECUTION_PLAN.md` §15.5 lists canonical case **C11**:

```text
C11  same claim, different producer     content_digest DIFFERENT
                                        (provenance is semantic)
```

**C11 cannot be exercised against an admitted record.** It requires two records
differing only in `producer`, and §6.5 registers exactly one producer token per
admitted event, so the second record is `REJECTED` by the §6.6 cross-field rules
before any digest is computed. There is no admitted pair to compare.

This was verified rather than reasoned about. A record was constructed for
several kinds and families with only `provenance.producer` changed:

```text
observation/SOURCE_READ      producer='ai-02'  -> REJECTED: ProducerNotRegistered
observation/SOURCE_READ      producer='ai-04'  -> REJECTED: ProducerNotRegistered
decision                     producer='ai-03'  -> REJECTED: ProducerNotRegistered
execution                    producer='ai-02'  -> REJECTED: ProducerNotRegistered
```

Every construction was refused. C11 has no reachable subject.

C11 is the only canonical case with this property: C1–C10 each vary a field the
registry does not pin (key order, set order, locator, `recorded_at`,
`evidence_id`, `observed_at`, artifact bytes, Context identity, `experiment_id`,
`producer_version`).

**What was done about it:**

* C11 is **not** deleted, not weakened, and not marked as passing.
* No invalid-but-admitted record was manufactured to satisfy it.
* No internal backdoor was added to bypass the registry.
* The classification C11 asserts **is** covered directly, by the two tests in
  §F, which read the real projection of admitted records.

**This is recorded as a limitation of the frozen contract's test model, not as a
defect in the implementation.** Closing C11 for real would require a contract
amendment — for instance a canonical case that varies a field the registry does
not pin, or an explicit statement that C11 is a table-level rather than a
record-level assertion. **This branch does not make that amendment**; the frozen
contract is untouched (blob-identical, §A).

The limitation is documented in the module docstring of
`tests/evidence/test_models.py`, in the file the tests live in, so a reader
encountering C11 in the contract finds the explanation where the tests are.

## I. What B1 is

A pure, offline logical core. It owns:

```text
the record model          envelope + typed per-family payloads, strict parsing
the field table           §15.2 as data, 52 leaf rows, two projections built by
                          walking it
the digests               content_digest (semantic equivalence) and
                          record_digest (everything stored), plus value_digest
the grammars              §14.9's thirteen named patterns
the registry              §6.5's six admitted events
the cross-field rules     §6.6 rejections
the error vocabulary      one error per reason, no value echoed
```

Two decisions are worth recording because they are the ones a later phase could
silently undo:

**Two digests, because one cannot do both jobs.** `content_digest` must be
invariant across promotion and relocation, or moving an artifact would change a
claim that did not change. `record_digest` must cover everything stored, or
repointing an `artifact_ref` would be invisible. Their requirements are opposite.

**`observed_at` is classified per `(kind, field)`, not per field.** Semantic for
`OBSERVATION` and `EXECUTION`, operational for `DECISION` — following AI-02
§11.6 on the one hand and AI-04 T14 on the other.
