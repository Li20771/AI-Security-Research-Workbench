## G. Guard integration

`ask_guard` calls AI-04's frozen `evaluate(request, policy)` and reads the
decision. It does not wrap, extend, shadow or reimplement it.

```text
ALLOW      the adapter runs
DENY       NOT_RUN, adapter not called
BLOCKED    BLOCKED, adapter not called
UNKNOWN    UNKNOWN, adapter not called
raising    BLOCKED with GUARD_UNAVAILABLE, adapter not called
```

The Guard request's workspace comes from AI-03's `resolve_workspace`, so the git
state is AI-03's answer rather than a second implementation of it. The policy is
a parameter, as AI-04 requires of every caller.

## H. Evidence integration

`plugins/security_tools/evidence.py` produces an AI-05 `ToolCall` and an
`ExecutionPayload`. AI-06 does not call admission, does not write a record and
defines no Evidence schema.

```text
ToolResult -> ToolCall(ordinal, what_ran="<tool_id>/<operation>", status)
```

`what_ran` carries no argument, no output and no environment. The outcome
projection is total and one-way, and `status_for` is called from exactly one
place (T32 asserts that by AST).

## I. Layer 0

`check_security_tools_boundary`, 15 checks total in Layer 0.

It parses with `ast` **and** exercises the package: a shell path no test happens
to take is a structural finding, and a registry that silently stopped agreeing
with the frozen vocabulary is a behavioural one. T47 mutates a copy of the tree
seven ways and requires the gate to fire on each.

One mutation is deliberately **not** detected, and the test records why:
disabling a single branch of the vehicle boundary leaves the remaining checks
still refusing a physical target. That is defence in depth working, not a gap.

## J. The secret boundary, stated as what is claimed

```text
CLAIMED      no credential is injected by AI-06
             the parent environment is never passed through (§11.2, T22)
             every result passes a named projection (§14.3)
             the projection is tested against known-shaped material (T28)
NOT CLAIMED  that no secret can appear in a tool result. A tool can print
             anything, and a projection is a bounded filter rather than a proof.
```

A defect was found here and fixed in the same PR: the projection masked
`Authorization: Bearer` and left the token in the clear, because the header
pattern's `\S+` stops at the space. The scheme pattern now runs first and the
header pattern consumes the whole line. Before the fix, that path would have put
a credential into a `ToolResult`.

## L. Amendment 1

Two fields the frozen text required a value for while naming no field to carry
it. Recorded in the contract's §22; neither is a new rule.

```text
OperationSpec.expected_exit_codes   §11.5 says the exit-code semantics are
                                    "stated in the OperationSpec" and §7.2 named
                                    no field. Without it the only implementation
                                    left is the general rule §11.5 forbids, and
                                    that rule would report a YARA match as a
                                    failure.

                                    `truncated` and no field for redaction. A
```

changed.
