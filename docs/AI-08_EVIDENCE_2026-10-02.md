## D. Amendment 3 — the Guard-bound invocation boundary

**A cross-phase contract conflict, found by this phase's implementation review.**
This is the substantive result of AI-08-B and is recorded first because
everything else in this document is measured against the contract *as amended*.

### D.1 The conflict

Three independent clauses quantified over **every** tool invocation:

```text
§12      "Every Agent tool call MUST carry ... a FRESH GuardRequest
          ... a FRESH GuardDecision"
§9.1 I5  "every tool invocation creates a FRESH GuardRequest and a FRESH
          GuardDecision."
§13.4    "a fresh GuardRequest and a fresh GuardDecision for EVERY tool
          invocation, per execution (§12, I5)"
```

AI-06 refuses on five paths **before** `ask_guard`:

```text
plugins/security_tools/dispatch.py:75   UNKNOWN_TOOL
plugins/security_tools/dispatch.py:79   UNKNOWN_OPERATION
plugins/security_tools/dispatch.py:85   invalid arguments
plugins/security_tools/dispatch.py:92   v1 target boundary
plugins/security_tools/dispatch.py:99   workspace resolution
plugins/security_tools/dispatch.py:109  ask_guard(...)   <- none of the above reach it
```

AI-06 states the consequence from its own side
(`plugins/security_tools/guards.py:211-219`):

> *"A refusal raised before `ask_guard` ... has no `DecisionRecord` to point at,
> and saying so is more honest than inventing an identifier. `decision_id` stays
> empty precisely because no evaluation produced one."*

So the universal could not be met. Closing it would have required duplicating
AI-06's gates inside AI-08, fabricating a `GuardDecision`, or changing AI-06 —
all three forbidden by §12 and by the phase's own constraints.

### D.2 The resolution

**Guard-bound semantics.** New §12.2 and §9.1.2 define the boundary; the
quantifier is narrowed to the invocations it can truthfully apply to, and a
pre-Guard refusal is named rather than left as an unmentioned hole.

```text
Guard-bound invocation   passed AI-06's pre-Guard gates and reached the Guard
                         authorization boundary. Carries a fresh GuardRequest
                         and a fresh GuardDecision.
Pre-Guard refusal        refused before that boundary. Has NO GuardDecision, and
                         none may be fabricated.
```

```text
FROZEN: an empty `guard_decision_id` means "no evaluation happened". It is NOT
        UNKNOWN and NOT BLOCKED. "No evaluation occurred" and "an evaluation
        returned BLOCKED" are two different facts.
```

Synchronised by the amendment: §9.1 I5 · §12 · §12.2 (new) · §9.1.2 (new) ·
§13.4 · §20 C9 · §21 · test matrix T20 reworded and T44 added.

**AI-06, AI-04, AI-05 and AI-07 are untouched by this amendment.** Verified:
`git diff --name-only main...HEAD` names nothing under `plugins/`, `providers/`,
`routing/` or `tools/`.

### D.4 A conflation this amendment found in AI-08's own code

`ToolCallRef` carried `guard_decision=BLOCKED` for a pre-Guard refusal, because
AI-06 supplies that word as a fallback alongside the empty id. Carrying it
recorded a non-evaluation as a decision — the exact conflation §12.2 forbids.

```text
BEFORE   guard_decision=BLOCKED, guard_decision_id=''   <- a claim nothing supports
AFTER    guard_decision=None,    guard_decision_id=''   <- the truthful state
```

`ToolCallRef.was_evaluated` reads the empty id, and `to_mapping()` serialises
`null` rather than a word.

## E. Review fix — identity boundary

**Defect.** `AgentExecutionRequest(agent_id="not-registered", ...)` constructed
successfully. A dataclass does not check annotations, so the declared `AgentId`
type was not enforced and `resolve_agent` was not the only boundary.

Two consequences, both reproduced before the fix:

```text
BLOCKED path     the runtime returns before it builds a ToolGateway, so an
                 AgentResult was produced with agent_id == 'not-registered' —
                 a result attributed to no registered Agent.

COMPLETED path   ToolGateway.__init__ called AgentId(...) on the way past, so a
                 ValueError escaped execute() entirely:
                     RAISED out of execute(): ValueError: 'not-registered' is
                     not a valid AgentId
                 which breaks §7.1.1, one terminal result per execution.
```

**Fix.** `AgentExecutionRequest.__post_init__` resolves through `resolve_agent` —
the same boundary, not a second rule beside it — and `AgentResult.agent_id` is a
real `AgentId` rather than `str`.

Measured after the fix:

```text
AgentExecutionRequest(agent_id="dsh")             -> AgentId.DSH
AgentExecutionRequest(agent_id="codex")           -> AgentId.CODEX
AgentExecutionRequest(agent_id=AgentId.DSH)       -> AgentId.DSH
AgentExecutionRequest(agent_id="not-registered")  -> UnknownAgent
AgentExecutionRequest(agent_id="gpt")             -> UnknownAgent
AgentExecutionRequest(agent_id="")                -> UnknownAgent

BLOCKED workspace + unknown Agent   -> refused at construction; the runtime is
                                       never reached, so no such AgentResult can
                                       exist
normal execution + unknown Agent    -> refused at construction; nothing escapes
                                       execute()
AgentResult(agent_id="gpt", ...)    -> UnknownAgent
AgentResult.agent_id                -> AgentId, always
```

Asserted by `tests/agents/test_identity.py::TestTheConstructorIsTheIdentityBoundary`
and `::TestAgentResultIdentityIsAnAgentId`, both of which drive the **real
constructor and runtime**. Testing `resolve_agent("gpt")` alone would not have
caught this defect, because `resolve_agent` was already correct.

## F. Review fix — result reference shape

**Defect.** `AgentResult.result` was caller convention only.

```text
BodyOutcome(result_ref="AWS_SECRET=abc123\nraw task body")
  -> written verbatim into a COMPLETED AgentResult
```

**Fix.** §10.2's invariant is now enforced at construction. The field admits
exactly two shapes:

```text
sha256:<64 lowercase hex>       a content digest
ref:<opaque reference token>    token restricted to [A-Za-z0-9._:-],
                                no whitespace, no CR, no LF, no '='
```

The runtime's own failure and block references moved onto the same grammar, so
neither path bypasses the rule:

```text
agent-block:<id>    ->  ref:agent-block:<id>
agent-failure:<id>  ->  ref:agent-failure:<id>
```

Measured — accepted and refused:

```text
ACCEPTED  sha256:<64 hex> · ref:agent-block:ex-0123456789abcdef · ref:x
REFUSED   "AWS_SECRET=abc123" · "raw task body" · "line one\nline two" ·
          "line one\r\nline two" · "" · uppercase hex · short digest ·
          "ref:" · "ref:has space" · "ref:has\nequals=sign" ·
          "not-a-reference" · None · 7
```

```text
COMPLETED  result = sha256:<64 hex>
FAILED     result = ref:agent-failure:<execution_id>
BLOCKED    result = ref:agent-block:<execution_id>
```

Asserted by `tests/agents/test_execution.py::TestTheResultReferenceShape`.

### F.1 What this guarantee is, and where it stops

```text
IS      a STRUCTURAL SHAPE guarantee. Obvious raw-content forms — multi-line
        text, `KEY=value` assignments, prose, whitespace, quotes — cannot be
        stored in AgentResult.result at all.
IS NOT  a universal secret-content classifier. A single-line secret that happens
        to match the token charset would still pass.
```

The complete answer to "is this value content-free" is a *published admission
rule set over bounded-source fields*, which is AI-05's deferred **C-1**. AI-08
does not become a content scanner to cover a gap another phase owns. This limit
is stated in `agents/result.py` next to the grammar itself, not only here.
