## 5. Recorded findings

### 5.1 AI-02's transport-confinement guard is a substring scan over three roots

`tests/unit/test_live_verification.py::TestLiveOnlyTransport` scans
`providers/`, `tests/` and `scripts/` for the strings `HttpTransport` and
`http_transport`. Any file under those roots that *names* the live transport
trips it — including prose in a docstring or a comment.

This bit during implementation: the first full-suite run failed with
`offenders == ['tests/integrations/test_backend.py',
'tests/integrations/test_integration_boundaries.py',
'scripts/ci/layer0_policy.py']` — three files that merely mentioned it.

```text
RESOLUTION: AI-02's guard was NOT modified. The AI-09 files were written so they
            do not name the live transport, and the property is asserted by the
            Layer 0 allowlist instead — which never needs to name it, because a
            whitelist excludes by omission.
COST:       AI-09 cannot carry a test whose source names the transport. The
            property is still covered, by `check_ai09_integration_layer()` and by
            `test_the_gate_is_not_vacuous`, which proves that gate fires.
STATUS:     recorded, not escalated. No AI-02 contract or artifact was changed.
```

### 5.2 `integrations/` is outside AI-02's guard roots

Exactly as AI-09 contract §10.4 recorded. AI-09's own Layer 0 check closes it,
and `tests/integrations/test_integration_boundaries.py` states that in place.

### 5.3 The backend issues plain-text invocations only

It sends no tool schema and no `response_format`, because the capability gate
refuses those requests while every capability is `UNKNOWN`, and the contract
forbids fabricating a verified profile to get through. Tool-calling and
structured-output compatibility are therefore observed at the protocol boundary
(§3.6) rather than through the backend. This is a designed consequence, not an
omission, and it will hold until a capability is promoted by a reviewed change.

### 5.4 A credential-boundary violation was found and corrected

An earlier revision of this layer had `MimoCodexBackend.__init__` take an
`environ: Mapping[str, str] | None` and forward it into an `InvocationContext`.

```text
WHY IT WAS A VIOLATION
    Contract §13 says the integration layer never sees, holds or passes the
    credential. The environment mapping IS the credential source, so holding it
    is holding the credential. That no key was read, logged or placed in a body
    is not the test — the test is possession.

ROOT CAUSE
    The backend assembled its own InvocationContext. Assembly is the moment the
    credential source enters an object, and it was happening inside the layer
    that must not have it.

CORRECTION — FIRST ATTEMPT, INCOMPLETE
    The backend was changed to take an already-built `Invoker`, and the
    assembly moved to `integrations/codex/composition.py`, with a Layer 0
    exception naming that file as the one module allowed to bind `environ`.

    That was still a violation, and the reasoning behind the exception was
    wrong. Contract §10.1 makes `integrations/codex/` the AI-09 boundary IN
    FULL, so a composition root placed inside the package is still the
    integration layer holding the credential source. The exception was
    implementation-invented; the contract authorises none.

CORRECTION — FINAL
    `integrations/codex/composition.py` is DELETED, and no production
    composition module replaces it. The credential-bearing InvocationContext is
    assembled outside `integrations/` by an external composition root and handed
    to the provider-side Invoker:

        external composition root -> InvocationContext(environ=...) + Invoker
                                  -> MimoCodexBackend(invoker=...)
                                  -> existing Invoker.invoke()

    Because this repository has no production application entry point that
    would own that wiring, it is the test suite that plays the external root:
    `invoker_factory` / `backend_factory` in tests/integrations/conftest.py.
    That is test wiring, not production architecture.

    `MimoCodexBackend` still takes {model_ref, config, providers, models,
    invoker, timeout_ms} and nothing credential-bearing.

ENFORCEMENT
    `AI09_CREDENTIAL_CONTEXT_MODULE` is deleted — there is no excepted file.
    Every production module under `integrations/` is refused if it binds the name
    `environ` at all, as a parameter, a local or an attribute, alongside
    CredentialRef, SecretValue, getenv and resolve. Verified to bite with no
    exception: reintroducing a composition helper into backend.py fails the gate;
    reverting it passes.

    No `providers/` change was needed, and none was made.
```

The correction is a tightening, not a new decision: §13 already said this, and
the implementation now matches it. The AI-09 contract was not amended.
