```text
ai11-v1-fuzzing-recovery-triage      BLOCKED            ecu-survives-and-recovers         PRECONDITION_UNMET:environment:vcan0-exclusive
```

A.6's recovery condition is a **subject-side** observation (§27.8): did the ECU survive,
did it answer the tracked probe `10 01` -> `50 01 00 32 00 64`, is no ECU process left
behind. It is not answered by judging an answer, and "the negative control was rejected"
cannot stand in for it. On this host it stops at the same exclusivity gate the task
oracle does, and it is recorded as BLOCKED rather than as a pass.

```text

evidence that §13's Agent-recovery model is complete.
§13 remains BLOCKED / DEFERRED. Nothing here unblocks it.
```

## 7. Known future design debt

Recorded, **not** resolved, and **not** worked around. The contract was not amended for
it and no control file was adjusted to dodge it.

```text
OBSERVATION
    A.6's tracked truth and control record:
        kernel_oracle = AVAILABLE
        kernel_events = 0
    measured on a controlled rerun of a host where dmesg was readable.

LEGAL SEMANTICS (§27.4, inherited from SecurityLab)
    AVAILABLE       -> integer count of matching kernel-anomaly lines
    UNAVAILABLE     -> null
    ERROR           -> null

FUTURE RISK
    If vcan0-exclusive ever becomes auditable and A.6 can run, on a host whose dmesg is
    UNAVAILABLE the rerun would lawfully observe `null` for every case, while the
    tracked known_good still declares 0. The static reference answer would then not be
    that host's reference answer, and the correct answer could be judged FAIL.

CURRENT IMPACT
    NONE on any production result. A.6 is BLOCKED at the exclusivity gate before a
    single case executes, so no run can reach the comparison.

STATUS
    FINAL-REVIEW OBSERVATION / FUTURE DESIGN DEBT
```
