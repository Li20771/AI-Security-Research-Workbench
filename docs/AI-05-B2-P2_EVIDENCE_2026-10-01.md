## C. What P2 implemented

### C.1 Stored-form round-trip (§17)

```text
EvidenceRecord.to_stored_mapping()   the §5 envelope, fully populated
stored.load_stored(mapping)          parse, validate, verify, return
```

§17 requires `re-read -> parse -> canonicalize -> hash == the SAME record_digest`.

### C.2 Generated-field restoration, stored path only

The fields a caller may never supply are read back on the stored path:
`evidence_id`, `recorded_at`, `content_digest`, `record_digest` and
`ContextRef.value_digest`. The two entry points are separate methods with
separate key sets — no `allow_generated_fields`, `allow_stored` or `mode=`
switch exists anywhere in the package, and every parser signature takes
`(raw, where)` and nothing else.

`from_mapping` still refuses all five. `ContextRef`'s two forms are disjoint:
the caller form requires a raw `value` and rejects `value_digest`; the stored
form requires `value_digest`, has no `value` key, and refuses a stored mapping
that carries one (§12.4).

### C.3 Stored integrity verification (§16, §17)

```text
stored.verify_stored_integrity(record)
  recompute content_digest  -> compare with stored
  recompute record_digest   -> compare with stored
```

The stored values are what is checked, never what is trusted. A mismatch raises
`StoredIntegrityFailure`; nothing is repaired, no digest is rewritten, and no
corrected record is returned. An attacker who rewrites **both** stored digests
still gets `STORED_INTEGRITY_FAILURE`, because recomputation wins over what the
bytes claim.

New error: `StoredIntegrityFailure` / `STORED_INTEGRITY_FAILURE`. It does not
reuse `CallerSuppliedDigest`, which is about digest ORIGIN, nor
`RecordMalformed`, which is a shape family — §22.2 gives "digest mismatch" its
own row.

### C.4 Why `record_projection()` is not the stored form

Checked against the code rather than assumed from the name:

```text
it omits record_digest     a digest MUST NOT be its own input, yet §17 requires
                           a stored record to carry it so a later reader can
                           verify the record with it
it is flat                 keyed by contract leaf paths (binding.source_kind)
                           where every payload parser reads a nested binding
the shapes disagree        it spells payload.reasons[] with brackets
                           DecisionPayload does not read, while
                           ExecutionPayload keeps them on tool_calls[]
its containers are paths   references.context[], not section names
```

Reusing it would also make the on-disk format a by-product of the §15.2 digest
table, so a future classification change would silently break the round-trip of
records already written. §20.4's D3 requires a written record to be readable by
a future session, so the two are kept separate: §15.2 decides what is hashed,
the stored mapping decides what is stored, and both are complete over the
persisted fields.

## F. Physical JSON round-trip — verified

R1–R8 are exercised through real JSON text, not dictionary-to-dictionary:

```text
EvidenceRecord -> to_stored_mapping() -> json.dumps -> json.loads
               -> load_stored -> EvidenceRecord
```

11 tests move bytes this way. §17 names the trap — a string that re-parses as a
number — and a dict-to-dict test would pass an implementation that stored
`ordinal` as `"0"`. Verified: `int` survives encode and decode, `record_digest`
is identical afterwards, and a stringified ordinal is refused.

```text

R2  value_digest restored; the raw value appears nowhere in the stored bytes
R3  recorded_at restored and re-validated on the way in
```

## J. Recorded, not hidden

- **`to_mapping` orders collections.** `References` and `Artifacts` emit their
  sets in `canonical_key` order, and `ExecutionPayload` emits tool calls in
  ordinal order. This is a choice for deterministic stored bytes, not a
  contract requirement — R8 passes either way, because the digest sorts
  independently. It is the one place the stored form applies an ordering
  decision that `canonical.py` also applies. Raised in the P2 audit as F2 and
  left as-is deliberately.
- **`to_stored_mapping()` does not refuse an unwritten record.** On a record
  with no digests it emits `{"content_digest": null, "record_digest": null}`,
  and `load_stored` then refuses it with `MISSING_REQUIRED_FIELD`. It fails
  safe, but later than it could. Raised as F4 and left as-is.
- **`EvidenceRecord.from_stored_mapping` does not exist.** The record-level
  stored entry point is `stored.load_stored`, named differently from
  `from_mapping` on purpose. Raised as F3.
- **The P2 audit found the report of P2's own diff was wrong.** The initial P2
  report stated `models.py +433 / -34` and `__init__.py +15 / -5`; the real
  figures were `+436 / -31` and `+12 / -3`. The totals were correct. The
  per-file numbers in this record are read from `git diff --numstat`.
- **P1 was missing from `PROJECT_STATUS.md`.** PR #41 was merged but never
  recorded, so the AI-05 status block jumped from B1 to P2 with no P1 entry.
  This closeout adds it; the merge chain is now complete and checkable.
